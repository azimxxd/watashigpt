# One-week pilot

## Question

Does ActionFlow become a tool people choose to use repeatedly when writing everyday messages?
This is a proposed study, not evidence of existing demand or measured product success.

## Participants

Invite 5–10 people who write messages/emails regularly, ideally in more than one language.
Do not require them to share their messages, API keys, screenshots or history files.

## First session (10–15 minutes)

Ask the participant to install the app, connect their chosen provider and complete one edit using
the practice sentence. Observe where they get stuck, with their consent. Then ask them to:

1. Fix a typo and inspect the changes before replacing.
2. Translate a non-private sentence and change the target language.
3. Type a custom instruction, save it and reuse it on different text.
4. Copy a result instead of replacing it, then try the documented undo workflow.

Record task completion, confusion and time to the first successful edit. Avoid intervening unless
they are blocked; record where help was needed.

## During the week

Let people use the tool in their normal work without daily reminders to use it. Local usage counts
are optional; explain that they contain aggregate counts only and are never uploaded. Participants
can view them in Settings and choose whether to share the numbers. Do not ask for the preferences
file, which can contain personally written saved instructions.

## Follow-up questions

- When did you remember to use it without prompting?
- Which action did you return to? Which action did you search for but not find?
- Did you reject results because of meaning, tone, formatting, latency or something else?
- Did you trust replacement? Was copying more useful?
- What did you do before installing it? Would you go back to that method?
- What would make you stop using the tool?

Compare generated/accepted/copied/discarded/failed counts if participants opt to share them.
Counts are not unique users or days of retention, and retries may inflate generation counts.
Use the interviews to interpret them. Practice is excluded from these counts.

## Decision

Choose success criteria before recruiting. For example, look for repeated unprompted use on
several days, a recurring writing task, and few failures or accidental changes. These are proposed
criteria, not industry benchmarks. Prioritize repeated barriers reported by multiple participants.
Do not add more commands until the core writing workflow demonstrates value.
